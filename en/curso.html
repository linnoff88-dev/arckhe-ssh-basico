Track · Lesson 1

What it is SSH

By the end of this lesson, you’ll recognize the 4 elements every remote connection command needs — without memorizing any code.

Today, when something gets stuck in the automation running on your VPS, you depend on messaging support and waiting. The next lessons will help you handle that yourself — but first, you need to understand what’s actually happening when someone “logs in” to a server. Without that foundation, every command is just memorization.

↓ scroll to study

01 The private corridor to your VPS

A VPS is a computer that stays on 24 hours a day in a data center, running your business’s automation. The SSH is the private corridor that connects your computer directly to that server — without having to travel to the data center.

After Marta, a beauty salon owner, connects via SSH to the VPS that runs automatic appointment confirmations over WhatsApp, everything she types runs there, not on her laptop.

02 What this corridor is for in practice

With SSH, you can log in to the VPS and take care of things yourself that currently require support: restart a stuck service, check why a message wasn't sent, edit a file, or just confirm that everything is working.

Ricardo, a clothing store owner, uses an automation that posts new collection items on its own. When it stops posting, SSH lets him access the VPS and see what happened that same minute — instead of waiting for someone to become available.

You don’t need to understand the entire server—you just need to know how to open the right door when necessary.

03 The 4 elements of every connection

Every SSH connection—Marta’s, Ricardo’s, anyone’s—always depends on the same 4 elements, no more and no less:

  • The SSH client — the program on your own computer that starts the conversation.
  • The SSH server — the service running inside the VPS, waiting for someone to knock.
  • The VPS IP — the public address that tells you where it is, like a house number.
  • A authentication — a password or key, proof that it’s really you logging in.

Test yourself

If you switch VPS providers (for example, Hostinger instead of AWS), which of the 4 elements changes?

04 What changes when you understand this

A connection command looks like a row of strange symbols the first time you see it. After this lesson, it’s just this: client, server, IP, and authentication, in a fixed order—nothing more.

Marta was looking at ssh root@123.123.123.123 like a puzzle. Now she knows: it’s her client (the ssh) authenticating a user (root) at an address (123.123.123.123) — the 4 elements, in the same order as always.

Before

A connection command was a block of text to copy without understanding, hoping it would work.

Then

The same command becomes 4 recognizable pieces—and you know which one to adjust when something changes.

01 Checking whether SSH is already on your Windows PC

This is a simple recipe: you open the terminal (CMD or PowerShell), type a check command and read the response.

Marta opens the Start menu, types "cmd," opens Command Prompt, and types ssh -V. If something like OpenSSH_for_Windows, SSH is already installed — she doesn't need to do anything else at this stage.

02 If it isn’t installed

If the command isn’t recognized, Windows 10/11 has SSH ready to enable, without downloading anything from elsewhere: Configurações → Apps → Recursos opcionais → Adicionar recurso → OpenSSH Client.

Ricardo ran into this at the store: the command returned an error the first time, he enabled the feature using the path above, reopened the terminal, and the ssh -V worked.

Common error

Test the command without closing and reopening the terminal after enabling the feature. Windows only recognizes SSH in a new window—close the old terminal and open another one before testing again.

03 The connection command and the first prompt

Once SSH is ready, connecting is just one line: ssh usuário@IP_DA_VPS. Marta types ssh root@123.123.123.123 (the IP is always the IP of her VPS, not this example).

The first time anyone connects to a new VPS, a question appears: Are you sure you want to continue connecting?. This is the computer confirming that you recognize this server—type yes and press Enter.

Test yourself

04 Typing the password (which doesn’t appear on screen)

After the yes, the VPS asks for the password. The first time, Ricardo thought the keyboard had frozen: no letters appeared as he typed.

That’s intentional: for security, the password never appears on screen, not even as dots. Type normally and press Enter — it’s being received; it just isn’t shown.

First connection checklist

  1. Open the terminal (CMD or PowerShell).
  2. Type ssh usuário@IP_DA_VPS with the details for your own VPS.
  3. The first time, type yes when prompted.
  4. Type the password (it won’t appear) and press Enter.

Moving around inside
from the server

By the end of this lesson, you’ll find your way around your VPS, move between folders, check basic information, and exit safely.

After logging in (lesson 2), the first surprise for anyone who’s never used a terminal is not knowing where they are or what to do next. These 5 commands solve 90% of “I’m lost” moments.

↓ scroll to study

01 Where you are and what’s here

Once you’re in, you can confirm two things: where you are and what’s around you. pwd shows the path to the current folder; ls lists the files and folders inside it.

Marta logs in to the VPS and types pwd and see something like /root — the “room” where it arrived. Then type ls and see the WhatsApp automation files stored there.

pwd
ls

command

$ pwd
$ ls
/root
automacao_whatsapp  config.json  logs

02 Moving between folders

To open a folder, use cd nome-da-pasta ("cd" for changing directories). To go back one folder, cd .. — the two dots mean “the folder above.”

Ricardo wants to see the folder for the post automation: he types cd automacao, confirm with pwd, and when you're done looking, type cd .. to return to where you came from.

Common error

Forgetting the space between “cd” and the folder name, or misspelling the name. The terminal is very literal— cdautomacao doesn’t work, and a wrong folder name returns "not found." Check with ls the exact name before you enter.

03 Viewing information and keeping the system up to date

uname -a shows system information (which Linux version is running). On servers based on Ubuntu or Debian—the most common ones for automation VPSs— sudo apt update && sudo apt upgrade -y updates the installed programs.

Marta runs this update once a month on the salon’s VPS, just like she updates her phone — it’s preventive maintenance, not a fix for a specific problem.

04 Exiting safely

To leave the VPS and return to your own computer, type exit and press Enter. The prompt changes back, confirming that you are no longer "inside" the server.

Ricardo finishes checking the automation and types exit, and sees the terminal on his own laptop again — a sign that any command he types now runs on the laptop, no longer on the VPS.

Basic navigation checklist

  1. pwd — where I am.
  2. ls — what’s here.
  3. cd nome / cd .. — enter / go back to a folder.
  4. exit — safely exit the VPS.

Understanding your
SSH keys

By the end of this lesson, you’ll identify which file is private and which is public in your computer’s key folder — and understand why having multiple keys is normal.

Starting with lesson 6, you’ll create your own key. Before that, you need to understand what an SSH key is and where it lives — otherwise, every next step becomes memorization all over again.

↓ scroll to study

01 Why having more than one key is normal

A SSH key is a way to log in without typing a password. And just as you have different keys for your house and car, it’s common to have a different SSH key for each service.

Marta has one key for the salon’s VPS and another for GitHub, where she keeps the automation code. They’re separate keys, each opening only the door it belongs to.

02 Where these keys live on your computer

On Windows, keys are stored in a hidden folder called .ssh, inside your user folder: C:\Users\SEU_USUARIO\.ssh\. On Linux or Mac, the same place is called ~/.ssh/.

Ricardo found his folder at C:\Users\ricardo\.ssh\ — the same pattern, just replacing it with his Windows username.

The folder .ssh is a drawer just for you — each key inside it opens a specific door.

03 Identifying the files inside the folder

Inside .ssh you may find names like id_ed25519, hostinger_vps.pub, config e known_hosts. The rule for recognizing it is simple:

  • File without .pub at the end = private key.
  • File with .pub at the end = public key.
  • config = connection shortcuts (lesson 8).
  • known_hosts = list of servers already confirmed (the "yes" question in lesson 2).

Test yourself

Marta sees two files: hostinger_vps e hostinger_vps.pub. Which one is the private key?

04 The golden rule: the private key never leaves here

The public key (.pub) can be placed on any VPS, on GitHub, on GitLab — it only serves to "recognize" the corresponding private key, never to log in by itself.

The private key should never be shared, copied to the public cloud, or sent in a message. Ricardo keeps his only on his own laptop, just as he keeps the store's physical key with him and never lends anyone a copy of the key.

Before

A single password that anyone can try to guess by trying over and over.

Then

A key pair: the public key shared wherever needed, the private key kept only by you—impossible to guess by repeated attempts.

  • Having more than one SSH key is normal—each service can have its own.
  • The keys live in the folder .ssh of your user account on Windows, Linux, or Mac.

Track · Lesson 5

CMD or PowerShell?

By the end of this lesson, you’ll recognize which terminal you’re in and avoid the most common syntax mistake people make when copying a command from the wrong place.

Windows has two different terminals, and a command that works in one won’t work in the other. It’s the #1 cause of “I copied it exactly and it didn’t work”—we’ll fix this before creating your key, in lesson 6.

↓ scroll to study

01 Why Windows has two terminals

Windows comes with two different terminals: CMD (Command Prompt, older) and PowerShell (newer, with more features). They both open a similar-looking window, but they understand different syntax for some things—like how to refer to your user folder.

Marta opened CMD without realizing it because she searched for "prompt" in the Start menu — PowerShell appears when you search for "powershell." Neither one is "the wrong one"; they’re just different.

02 The error that comes up most often: mixing the syntax of the two

Ricardo was in CMD, at the path C:\Users\ricardo\projetos\testes>, and tried to run type $env:USERPROFILE\.ssh\id_ed25519.pub — a PowerShell command typed inside CMD.

Common error

Use $env:USERPROFILE inside CMD (or %USERPROFILE% inside PowerShell). The error looks something like “the filename syntax... is incorrect”—because $env:USERPROFILE is PowerShell syntax, and CMD doesn’t understand it.

03 The translation between the two

The rule is: in CMD, your user folder is written as %USERPROFILE%; in PowerShell, you write $env:USERPROFILE. It's the same place, just with a different "word" for each terminal.

Marta learned to check the window title or the prompt itself: if you see only a simple path like C:\Users\marta>, it's usually CMD; if you see PS C:\Users\marta> with “PS” at the beginning, it’s PowerShell.

04 Checklist before copying any command

From now on, every command that involves %USERPROFILE% or $env:USERPROFILE in this learning path indicates which of the two terminals it’s for—check before pasting. That was exactly the habit that kept Ricardo’s same mistake from happening again with Marta.

Quick checklist

  1. Look at the prompt: does it start with “PS”? That’s PowerShell. If not, it’s CMD.
  2. In CMD, use %USERPROFILE%.
  3. In PowerShell, use $env:USERPROFILE.
  4. Got a syntax error? Check that you’re in the right terminal for the command.

01 Viewing an existing key

Before creating a new key, it’s worth seeing what a public key looks like: a long string of text that starts with ssh-ed25519. In CMD, type shows the contents of a text file.

Marta already has the key id_ed25519.pub from an old test; it runs type %USERPROFILE%\.ssh\id_ed25519.pub and see something like ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAA... minha-vps.

02 Opening the .ssh folder in File Explorer, if you’d rather see it

If you’d rather see the files as icons instead of text, the command explorer %USERPROFILE%\.ssh opens the folder in Windows Explorer, the same window you always use to view files.

Ricardo prefers this way: he types the command, Explorer opens, and he sees the files hostinger_vps e hostinger_vps.pub side by side, the way you’re already used to viewing folders.

Common error

Drag or copy the private key out of this folder "just to keep it somewhere easier to find." Any copy of the private key somewhere else (desktop, personal cloud storage) is one more copy that could leak — keep it only in there.

03 Creating the key, step by step

The type of key recommended today is ed25519 — more modern and secure. The creation command asks for a path and a name for your new key.

Marta chooses to call hers minha_vps, in CMD:

ssh-keygen -t ed25519 -C "minha-vps" -f %USERPROFILE%\.ssh\minha_vps

correct command

$ ssh-keygen -t ed25519 -C "minha-vps" -f %USERPROFILE%\.ssh\minha_vps

Your public key has been saved in minha_vps.pub

common error

(já existe uma chave com esse nome — escolha outro nome em vez de sobrescrever sem querer)

After that, just press Enter for the following prompts (they ask for an optional extra password for the key — you can leave it blank and confirm).

04 What the key generation creates

The command from the previous step creates two files: minha_vps (private key — never share it) and minha_vps.pub (public key — can go on the VPS).

Ricardo checks the two files in his folder and can already tell which is which, applying the rule from lesson 4: no .pub is private, with .pub is public.

Checking your new key

  1. Run the ssh-keygen with -f pointing to the chosen name.
  2. Press Enter at the following prompts.
  3. Check the 2 new files: one private, one .pub.

01 The problem with always repeating the same thing

02 Creating the config file

On your computer, inside the folder .ssh, you can create a file named exactly config (with no extension), with a block similar to this:

Host hostinger
    HostName 123.123.123.123
    User root
    IdentityFile ~/.ssh/minha_vps

Marta creates hers with the nickname salao, replacing the IP and username with the ones for her own VPS.

Common error

Forgetting the indentation (spaces) before each line after “Host”. The config file follows a format where the lines below “Host” need to be indented—without that, connecting with the nickname won’t work.

correct command

$ ssh hostinger

(o arquivo config existe, mas as linhas abaixo de "Host" nêo estavam recuadas)

03 What each line in the file means

Host is the nickname you choose (the name you’ll type). HostName is the VPS’s real IP address. User is the user. IdentityFile points to the private key that should be used.

Solving the
most common errors common

By the end of this lesson, you’ll diagnose the 4 most common connection errors on your own and know what action to take for each one.

At some point, a connection will fail — that’s normal and doesn’t mean you’ve done something fundamentally wrong. What makes all the difference is recognizing the message and knowing where to start investigating.

↓ scroll to study

01 Reading the error message is the first step

SSH always returns a message when something fails—and that message already points you in the right direction for troubleshooting. The 4 most common ones are: Permission denied, Connection timed out, Connection refused, and an error saying the "fingerprint" had changed.

Marta, the first time she saw Permission denied, thought he had broken something. He hadn't: he'd just typed the wrong username.

02 "Permission denied"

This message means the connection reached the VPS, but authentication failed. The most common causes are: wrong password, wrong user, wrong key, or the public key wasn’t added to authorized_keys, or the folder permissions .ssh are wrong (lesson 7). That was exactly the message Marta saw on her first attempt, because she typed the wrong username.

Common error

"Permission denied" when trying to connect to -i using the key. Before suspecting the key itself, check: the file authorized_keys has exactly the right key pasted in, and the permissions are set to 700/600.

03 "Connection timed out," "Connection refused," and an old key

Connection timed out means the request never got a response — usually the IP is wrong, the VPS is turned off, or a port is blocked by a firewall. Connection refused means the VPS responded with "no" — the SSH service may be turned off on it, or the port being used is wrong.

Ricardo recreated the store’s VPS once, and when he tried to connect again, he got a warning that the server’s “fingerprint” had changed — the command ssh-keygen -R IP_DA_VPS clears the old saved signature and lets you connect again, accepting the new one.

04 Checking the SSH service directly on the VPS

If you’re already on the VPS (for example, by logging in with a password after a key failure), systemctl status ssh (or sshd, depending on the system) shows whether the service is active. Ricardo used this command when the store's post automation stopped responding, and confirmed that the service was running — the problem was something else.

systemctl status ssh
sudo systemctl enable ssh
sudo systemctl start ssh
